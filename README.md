## 这是什么

`WorkBuddy2API` 把腾讯 CodeBuddy（`copilot.tencent.com`）的账号包装成**统一的 OpenAI
兼容接口**。官方不提供 OpenAI 形态的开放 API，本项目通过 OAuth 设备授权取得凭证，
在网关侧做 token 自动刷新、**账号池调度**与**流量治理**。

面向**个人多账号**场景。对客户端只暴露 OpenAI 兼容接口，现有 SDK / 前端 / 工具零改造接入。

| 你原本要做的 | 本项目的做法 |
|---|---|
| 一个账号用完就没了 | **账号池轮转** —— 多号共享、单号故障自动换号 |
| 上游 429 / 挂掉就雪崩 | **熔断 + 分级冷却**（软限流指数退避 · 402 硬冷却至次日 · 5xx 熔断） |
| 多轮对话中途莫名换号 | **会话粘性** —— 同一对话尽量绑同一账号，跨重启不丢 |
| 不知道怎么管几十个号 | **中文 Web 面板** —— 账号池视图、积分明细、签到/任务、出口线路、诊断 |
| 手动跑签到脚本 | **定时任务** —— 签到 / 活跃 / 旅行 / 保活四类独立开关 |
| 加号怕被关联 | **导入防关联门禁**（换 IP + 单批上限）+ 每号独立设备标识 + 出口单绑定 |
| 不知道谁用了多少 | 每次调用的模型、Token、上游账号、扣费、会话键全量留痕 |

## 功能亮点

### 账号池治理

- **加权轮转** —— 三因子加权随机（额度 / 快过期积分 / 闲置补偿）+ Top5 短名单 + 防撞号窗口
- **模型名写法归一** —— 入口把客户端传来的模型名折回上游认得的写法（去空白/零宽字符 →
  剥 `cn:`/`global:` 与 `[cn:]`/`[global:]` 前缀 → 与已知清单唯一匹配时做大小写/分隔符归一，
  匹配不上原样送出，**绝不猜模型**）；出站体带上规范名，冷却与负缓存键也随之收敛 ——
  同一模型不会再被当成两个模型（写错写法此前是"上游 400 → 客户端 404"的必然失败）
- **用户控制台「设置」页 + 右上角提醒中心**（v0.31.20）—— 设置页只放**用户自己有权处置的事**：
  账户 / 接入信息 / **我的出口**（为自己代挂账号配出口代理）/ 外观 / 提醒 / 关于；
  平台级配置（全局默认出口、计费倍率、线路池）不进用户侧。提醒中心（两端共用）把三类信息留在
  右上角：**操作反馈**（复制成功/失败等，从 `toast()` 自动落一份，可回溯）、**待办**（入池邀请）、
  以及 **`window.onerror` / `unhandledrejection`** —— "点了某个页面报错"从此有**可复制的原文与堆栈**，
  不必再靠记忆描述。存 localStorage（最近 50 条，同文 10 秒内去重）。
- **消耗「归属」拆分**（v0.31.20）—— 新增 `GET /api/me/usage-split` 与 `GET /api/admin/usage-split`：
  用户端概览看「**号池计费（扣余额）vs 代挂自用（不扣余额）**」；管理后台实时概览看
  「**平台自持号 vs 用户代挂号（按分成结算）**」。口径：只统计 `status='ok'`、窗口一律 `localDayStart`、
  管理端排除 `user_id=0`（管理通道按设计不计费）、**缺桶补 0**（SQL 的 GROUP BY 只返回有数据的桶，
  不补就会让前端读到 `undefined 次`）。报表域契约（`internal/api/report`）未动 —— 新问题用新接口，
  不改被多处消费的旧形状。
- **冷却／风控机制的「代挂号 vs 平台号」一致性审查**（v0.31.20）—— 一次独立审查的产出：
  三套机制（模型级冷却 / 账号级软冷却 / 风控摘号）在池层与 upstream 层**均无 `owner` 分支**，
  两类账号走同一套代码与阈值 ✅；但审出两处**链路间**漂移并修复：
  （a）同一个 `11140`，转发链软冷却 **2h**、健康检测链却只用 **60s** → 体检几分钟内重复触发 3 次
  就能凑满阈值摘掉健康号（正是"同一错误码两套纪律"那条历史教训的形态），已收敛为同源常量；
  （b）**未入池的代挂号**（`pending`/`invited`/`rejected`）不参与平台流量，却照样被探活并可能被
  停用 / 不可逆删除 —— 对用户资产的越权处置，且与"入池要号主同意"直接冲突；现在候选集排除它们，
  处置入口再加一道护栏（**只报告不处置**）。两条都有回归用例（`health_guard_test.go`）。
- **入池改为「邀请制」**（v0.31.18）—— 管理端的「批准入池」此前对**任何**代挂号都直接落 `in`，
  于是管理员能把一个号主**从未申请入池**的号拉进平台号池消耗他的积分，而界面文案写的是"批准入池"。
  现在按**来源**分流：号主申请过（`pending`）→ 审批落 `in`；没申请过 → **邀请**落新的 `invited` 态，
  **号主自己接受才入池**（`invited` 期间零消耗、零出站）。用户端有提醒条 + 侧栏角标，管理端按钮与
  队列同步区分（待审 / 已邀请待确认）。
- **`route-drift`：前端 `/api` 路径与后端路由表的源码级比对**（v0.31.19）—— 管理后台「预览方案 /
  执行分配」曾打的是 `/api/admin/egress/pool/assign`，而路由表里只有 `/api/admin/egress/assign`，
  于是**批量分配整块一直是 404**：jsdom 用例的 `fetch` 是桩、不看路径，Go 用例直接调 handler、绕过路由，
  两边都"测过"却没有一处把两边放在一起比。现在 `tools/uitest.mjs` 会从 `main.go` 抽出全部路由，
  与前端所有 `/api` 字面量逐一比对（`{id}` 视作通配）—— 首次运行即抓出这一条，其余 152 条零漂移。
- **插件「用户级启停」**（v0.31.22）—— 插件中心此前**只有管理端有开关**，用户端卡片只能看不能动，
  于是「可安装 / 可不安装」这件事在用户侧根本不存在。现在分两层，互不影响：
  管理端的开关是**平台级**（该能力是否提供给用户），用户端各自有一个**用户级**开关
  （`plugin_user_off_<userID>_<pluginID>`，缺省启用）。口径写死在服务端一处：
  `active = 平台启用 && 用户启用` —— 平台关则一律不可用，用户关则只有他自己不可用。
  用户停用后**执行接口真的拒绝**（不是只藏入口，否则直接调接口就能绕过）。
- **`.switch` 开关「点不动」的修复**（v0.31.22）—— 本项目 `.switch` 把真实 input 做成 0×0 透明，
  因此**只有被 `<label>` 包裹时**点击才会落到它上；而 admin/dashboard 里有四处是裸写的
  （「启用定时任务」「开放注册」「调试对话-流式」×2）：它们**看起来是开关、实际一直是坏的**。
  这类问题的麻烦在于用户不会报「开关坏了」，只会觉得「设了没用」。修法是加一次事件委托兜底，
  并补 `uitest.mjs` 的**行为级**守卫 `switch-clickable`（真点一下，看 `checked` 变不变、
  插件开关是否打到**本端**接口）。教训：**开关的"可点"是行为，源码长得再对也证明不了它。**
- **成长任务脚本链路的部署自查**（v0.31.22）—— 「脚本链路不可用」的真实原因常是**部署时漏拷
  `scripts/`**（python 其实是好的），而旧文案只写「缺少 python 或 scripts/growth_run.py」，
  既不说缺哪一项、也不说去哪里找。现在 `scheduler.GrowthDiagnosis()` 逐项报
  「脚本根 / 脚本存在性 / 解释器可用性」，管理后台直接显示这行诊断，部署文档也把
  「`scripts/` 必须与 `webapp` 同级」写成显式警示。

- **「用户代理」按钮全自动化**（v0.31.25）—— 点一下就好，不再复制粘贴任何参数或密钥：
  · **一键安装**：控制台「① 下载本机代理安装包」→ 一个按当前用户动态生成的 `.bat`
    （只含服务地址 + 他自己的令牌，**不含密钥材料**）→ 在目标电脑上双击运行 →
    页面进入「等待接入」轮询，检测到那台电脑就**自动接着拉起**。全程两个动作；
  · **每用户一把受限密钥**：agent 建反向隧道原本要一把能登录服务器的 SSH 私钥，
    而部署用的是 root 那把 —— 分发给用户等于每人一个 root，不分发用户就拉不起来。
    现在服务端为每人 ssh-keygen 一把，写 authorized_keys 时带
    `restrict,command="/bin/true",port-forwarding,permitlisten="127.0.0.1:12xxx"×10`；
  · ⚠️ **实测纠正了一个想当然**：**`restrict` 并不禁止 exec**（`ssh -i key host 'id'`
    照样能跑），必须再加 `command="/bin/true"`；顶替后 `ssh -N -R` 的转发不受影响，
    而 `permitlisten` 精确挡住段外端口（平台自己的 11080 与别人的 12040 都被服务端拒绝）；
  · **端口分区**：平台 11080-11089、用户 `12000+(uid%1000)*10`..+9；老机器下次 poll 时
    **幂等迁回本段**（否则会被 permitlisten 拒而表现为"连不通"）；
  · **并发防护**：`pull` 去抖（重复下发不刷新指令 At，否则 agent 会把隧道拆了又建）、
    `apply` 单飞（并发第二个 409，且该检查刻意放在隧道检查**之前** —— 否则连点第二次
    会得到误导性的"隧道未就绪"）；前端失败提示统一把原文翻译成下一步（**原文一律保留**）。
- **出口拉起的权限下沉：每个用户管自己的机器**（v0.31.24）—— 此前三个执行端点
  （`pull` / `release` / `apply`）挂的是 `adminGuard`，普通用户在控制台点「一键拉起」只会拿到
  **403**，前端又把操作区整块隐藏 —— "我的号从哪个 IP 出去"这件事只能由管理员代劳，
  等于把每个人的出站链路都挂在一个人手上。现在：
  · **机器按 owner 命名空间隔离**（表键 `u12:abc` / `abc` / `default`）——
    machine id 是 agent 自己生成、随查询参数上行的，构造成本为零，不带前缀时
    猜到/复用一个别人的 id 就能顶掉对方的桶；
  · **agent 令牌按用户签发**（`ag<uid>-<hex>`，服务端解析出 uid 只比对那一把）——
    共用一把时任何拿到它的人都能抢注 machine id、伪造别人的在线状态；
  · **视图按 owner 过滤** + `manage_scope`（platform / self）驱动前端文案；
  · ⚠️ **用户视角不设全局默认出口、不碰别人的号**：全局默认出口是平台级决定
    （同时决定所有平台号与所有"跟随默认"的账号从哪出去），而用户提供的代理是我们
    控制不了的第三方，只应承载它主人的号。用户拉起的线路仍进线路池（带 owner），
    管理员可显式分配给别人；
  · **拒绝话术合并**："这台不存在"与"这台不是你的"用同一句 —— 分开说等于给出一个
    能枚举别人 machine id 的探针；`pull` 也不再凭空登记机器。
  测试绝大多数是**负向断言**（看不到 / 动不了 / 改不了），三处关键实现都做过**变异检验**。
- **出口线路池：归属 + 实时 + 统一分配**（v0.31.23）—— 多用户各自配了自己的出口之后，
  管理后台需要把**每一台不同出口的机主**映射成一条**可独立分配**的线路。此前线路池只有
  「有哪些 URL」，看不出某条线是平台手填、agent 拉起、还是**某个用户自己配的**：
  现在 `egress_proxies` 有 `owner_user_id`（**粘性** —— 只允许从 0 变非 0 一次，
  后来者不得抹掉先认领的），用户在控制台「设置 → 我的出口」配好即**自动入池**、
  名称带用户名、地区是代理主机；代理页**5 秒轮询**（用户在别处配好，管理员这里自己出现），
  线路卡显示「来源」（本机 agent / 用户「X」配置 / 管理员手工录入）与「在用归属」
  （谁的号正跑在这条线上）。未登记线路卡可直接「**收录并分配**」一步到位。
- ⚠️ **用户线路只能被"显式指名"分配**（v0.31.23，本版最重要的一条边界）——
  用户提供的出口**不进自动选线、也不当自动迁移落点**。理由不是配置问题而是**泄露**：
  自动迁移是「把坏线路上的号搬到最闲的好线路上」，若用户线路在候选里，别人的号会被
  **自动**搬到一条我们控制不了的第三方出口上，而那些请求带着 `access_token`（bearer 凭证）。
  两条路径都已加排除，各配一条**决定性**用例并在本地做过**变异检验**（移除排除 → 用例立刻红）。
- **修「代理页线路卡一张都渲染不出来」**（v0.31.23）—— `EgressProxy` 此前**没有 json tag**，
  Go 用**字段名**（`Name`/`URL`/`LastIP`）序列化，而前端读 `p.name`/`p.url`，
  于是 `(p.name || p.url).charAt(0)` 抛 `TypeError` —— 整块线路池画不出来，
  而异常被 `loadEgress` 自己的 try/catch **吞成一句 toast**，页面上只剩空白：
  既看不出是前端 bug，也看不出是真没数据（这也正是此前「后台未显示代理路线」的真正底层原因）。
  已补 json tag，并两头都加了守卫：Go 侧 `TestEgressProxiesShape` 做键名**双向断言**，
  前端侧 `uitest.mjs` 的 **`egr-cards`** 按行为断言「喂一份线路数据必须画出卡片」。

- **本地出口代理「一键拉起」**（v0.31.17）—— 控制台新增「代理」页：点一下就把
  「你家里的网络出口」接进平台出站链路（本机代理 + SSH 反向隧道），并**自动应用**：
  注册线路（**id 按 URL 派生**，重复拉起不堆线路）→ 设全局默认出口 → **显式绑定自挂号**。
  通道是 `GET /api/agent/poll` + `POST /api/agent/report`（专用令牌 `X-Agent-Token`，只够这两件事）；
  **用轮询而不是服务端推**：本机在家庭 NAT 后面，云端无法主动连它，反向隧道也不解决
  「云端让本机执行命令」—— 轮询是唯一不开入站端口、也不必在本机跑 SSH 服务端的做法。
  状态查询对登录用户只读开放；**拉起/停止/应用仅管理员**（改的是全平台链路）。
  交付件在 `dist/egress-agent/`（agent + 本地代理 + 使用说明）。
- **自挂反向代理的端到端验证**（v0.31.17）—— 自用 Key 打 `/v1` **反复多次都只落在自己的号**
  （池里同时有平台号与**别人的**自挂号，所以这条断言真在挑串号）；平台 Key 正常服务
  （自挂号**入池后**平台流量可以选它 —— 那正是「申请进池」的含义，不是串号）；
  自挂号 `egress_proxy` 入库为空 → **跟随全局默认出口**（= 本地住宅线路）。
- **「模型名不存在」不再犁全池**（v0.31.16）—— `11102 model not available` 是**与账号无关**的错误，
  但网关照常换号重试（`maxAttempts=3`），于是**一次假模型名的请求会打 3 个账号**并各写一条 6h
  的 (账号,模型) 负缓存。实测事故：测速用的 `{"model":"x"}` 打了约 11 次 → **32/33 个账号**被污染。
  现在由 `rotateguard.ModelBlockGate`（**按模型名分桶**的跨账号 fail-fast，与既有 WAFGate 同源）兜住：
  **两个不同号**在 60s 内接连 11102 即判定「上游没有这个模型名」，当轮停止换号，激活期内**入口直接
  拒绝、零出站**。分桶是刻意的 —— 一个打错的模型名不该牵连真模型；判定**只作用于模型名，不处置账号**。
- **插件中心**（v0.31.16）—— 注册表驱动的**可启停功能单元**，管理后台与控制台各有「插件」入口。
  首个插件「多账号领取积分补偿」复用既有 `upstream.ClaimCompensation`（幂等，有则领）。
  **加插件不必再动导航结构**；停用只影响入口与执行，**不改动任何数据**。
  ⚠️ 出站纪律：执行接口**一次只处理一个账号**（多传 uid 直接 400），批量由前端**串行**完成
  （间隔 350ms）+ 服务端 `pluginGate`（全局在途 ≤3、同号 30s 一次）—— 禁止「一次请求打 N 次上游」
  那种无法限流的形态；失败**不处置账号**（不冷却/不熔断）。
- **入站请求体读取失败：措辞不改、状态码变准、现场留痕**（v0.31.14）—— `read body: unexpected EOF` 是
  **发送侧**成因（声明长度 ≠ 实际到达字节：客户端库 / 反代 / 隧道截断）—— 网关无法判断是哪一段网络，
  也不该替客户端猜；它的责任只有两件：**如实回报 + 留下现场**。此前这条分支**一个字节的痕迹都不留**，
  于是「客户端自己截断」与「中间层吃掉请求体」在本机无法区分；现在打一条带
  `peer / xff / content_length / 已读 / 耗时 / ua` 的 WARN —— 其中 `content_length=200 已读=39`
  这一对就是定性关键（声明多少 vs 实际到了多少）。另外把 `io.LimitReader` 换成 `http.MaxBytesReader`：
  前者到上限返回 **EOF 而不是错误**，8MB 以上的请求体会被**静默截断**，客户端看到的是把「请求太大」
  说成「JSON 写坏了」的 `invalid json: unexpected end of JSON input`；现在超限回 **413** 并写明上限。
  `error.message` **逐字保留** Go 原错（用户报障贴的就是它），补充说明走**并列**的 `gateway_hint`。
  **状态码（v0.31.15 真机纠错）**：传输中断回 **408**（不是 400）—— 400 会让 OpenAI 兼容 SDK
  **放弃重试**（重试名单是 408/409/429/5xx），而"上传被截断"是瞬时故障、重发通常就过；
  超限仍是 413（同一个超限请求重发多少次都还是超限）。
- **失败台账区分「上游 HTTP」与「回客户端」** —— 上游对「模型不存在」固定回 400，
  而我们回 404；两列并列后不会再把它读成"网关整站 400"
- **admin HTTP 面的共享层**（v0.31.12）—— `internal/httpx`：`WriteJSON` + **内部错误文本脱敏**
  （原 `cmd/webapp/errsafe.go`）。它们是每个 handler 的横切关注点（552 处调用），
  `internal/api/*` 各自复制一份就会让脱敏策略出现多个版本。
  **本包只放"对所有 handler 都一样"的东西** —— 带业务判断的写出留在业务域，否则它会变成第二个上帝对象；
- **用量报表域**（v0.31.13）—— `internal/api/report`：消耗排行（管理端 / 用户侧）+ 用量账单三类拆分
  （自用 / 用号池 / 进号池）。依赖面是 **7 个只读聚合方法 + 0 个自有类型**（`host_earnings` 的三个聚合
  先下沉到 `internal/usage`，靠 Store 嵌入做到零调用点改动）；身份由调用方**注入**
  （`UserIDOf` 回 `(id, ok)` 显式布尔，不用 `id == 0` 去推断"没登录"）。
  用户侧榜单**他人用户名一律脱敏、且不给他人 `user_id`** —— 排行榜天然要展示别人，不脱敏等于半张
  开着的账号名录；故管理端与用户侧**共用同一计算**，只有展示口径不同；
- **结算编排单点**（v0.31.11）—— "什么时候记账、按什么顺序记"在 `internal/billing/settle.go`：
  预扣对账 → 扣费/退还 → 写流水；所有 IO 走**窄接口** `billing.Ledger`（5 个方法，由
  `cmd/webapp/billingledger.go` 用 Store 适配，**只转发不判断**）。分成/返点仍由 `cmd/webapp` 执行
  （它要"号归谁、是否已入池"这类选号侧状态），新包只通过 `Result.HostCreditDue` 通知。
  → 于是结算可以用**一个假 Ledger** 单测，不必起 app / 库 / 假上游；
- **钱的口径单点**（v0.31.10）—— 单位换算（`MicroPerPoint` / `PointToMicro` / `MicroToPoint`）、
  用量估算、预扣额（下限/上限/折算）、单价观测（除零守卫 + 取历史最大值）、
  以及**分成与返点公式**（`HostEarn` / `ReferralRebate`）全部在 `internal/billing` 且被独立测试钉住。
  两条硬约束有**不变量测试**：分成 ≤ 平台实收、返点 ≤ 平台留成（`earn + rebate ≤ charged`）——
  破了就是每笔倒贴，且不会报错。运维须知：**要让平台每次都留成，必须「计费倍率 > 代挂分成比例」**；
- **分级冷却** —— 429 软冷却指数退避 · 6004 模型级冷却对齐上游重置墙钟（并有**半开探测**提前发现上游解除，见下） · 402 硬冷却至次日 04:00 · 5xx 熔断
- **错误分类处置** —— 上游业务码逐个定级（11101 不罚号 / 11128 渠道级不罚号 / 11140 累计阈值才摘 / 12153 连续计数）
- **运行态九态** —— `online` / `cooling` / `rate_limited` / `risk_cooling` / `exhausted` / `relogin` / `egress_error` / `disabled` / `manual_disabled`
- **两个独立停用位** —— 运维手动停用与系统判定禁用各自独立，恢复时各清各的
- **存量自愈** —— 启动时纠正两类历史脏状态：6004 被误写成账号级冷却、模型级冷却被账号级上限截断
- **已挂载天数** —— 账号卡与代挂卡显示「已挂载 N 天（起算日）」，口径为入库时刻起算的自然日数；
  时刻缺失时**不显示**该行（`0 天` 会被读成"刚挂上"，与"不知道挂了多久"相反）
- **更新检测与自动下载** —— 发现新版本自动下载产物（**sha256 必校验**、只落盘 `*.new`、
  **不动运行中的程序**），面板展示逐行版本说明与产物三态，并提供「应用更新」生成替换脚本。
  产物随 **GitHub Release** 发布（`version.json` 的 `assets` 按平台列出 url / sha256 / size，
  windows-amd64 已填）；发布用 `release.py`（上传前校验"清单声明的 sha256 == 实际字节"，
  不一致就拒绝 —— 否则线上会下到一个永远校验失败的文件）。
  ⚠️ 清单客户端对**本机/内网目标直连**（`internal/egress.Bypass` 同一判据）：Go 的 httpproxy
  只特判 `localhost`，`127.0.0.1` / `10.x` / `192.168.x` 会被照发给环境代理并拦成 502 ——
  「清单放内网文件服务」这种正当用法曾因此表现为"更新检查莫名失败"（v0.31.8 修）；
  ⚠️ 更新**检查**走仓库清单（`raw` 候选 + `api.github.com` Contents API 回退），
  更新**下载**走 Release 资产地址（`github.com` → 其 CDN）—— 两者可达性可以不同，
  本机实测 `raw.githubusercontent.com` 与 `github.com` 均不可达、只有 `api.github.com` 通，
  所以本机**只能检查不能下载**（下载失败会如实报错，不会静默）
- **提现提交即冻结** —— 申请时就把金额从可提现额度划入冻结额，等待审核期间用户怎么消费
  都不影响审核通过（旧实现只在查询时减待审额，余额被消费掉 → 审核必然失败）；
  通过从冻结额出账、驳回原路退回；同一笔额度无法被申请两次
- **提现审核方式可配** —— 人工逐笔审核（默认）/ 自动审核（提交即通过并打款），
  并可设**免审额度上限**（小额免审、大额仍进人工队列）。两种方式走**同一条出账实现**：
  通过 ⇒ 状态「已打款」+ 余额与冻结额同减 + 可提现额度钳到 ≤ 余额；驳回 ⇒ 冻结额原路退回。
  自动放行的记录带 `auto` 标记（审核人字段为空即如实表示「没有人审它」）
- **提现账目一致性自检** —— 冻结额合计 vs Σ(待审申请额) / `可提现+冻结 > 余额` 的用户数 /
  已处理却未记账的记录；**只是"发现问题"不自动修**（金额类差异先看见再决定），
  一致时界面不显示任何横幅
- **资金操作可追溯** —— 每次人工余额调整落审计（操作人 / 时间 / 变动值 / 改动前后余额 /
  原因 / 结果，失败也记）；用户卡「记录」按钮直接查
- **计费倍率可视化** —— 当前倍率 + 涨跌趋势 + 逐条调价记录（后台含调整人）；
  倍率变更**自动**向用户控制台发布临时公告（默认 7 天），不靠人记得发
  （**只放长不缩短**，且只在字段自相矛盾时动手）

### 防风控

- **出口线路池** —— 多线路 + 权重 + 停用 + **账号单绑定** + 全局兜底；真实出口 IP 探活；坏线路自动摘除
- **不静默换出口**（默认）—— 线路失效时账号留在原线路并排除出选号，**绝不回落直连**（换出口在上游眼里就是特征变化）
- **本机 / 内网目标不经代理** —— loopback / 私网 / CGNAT / 容器别名一律直连
- **每号独立设备标识** —— `X-Device-Token`（每号 > 全局 > 文件兜底）+ 按 uid 稳定派生的机器/会话 ID
- **设备凭证共用检测** —— 全池共用一个凭证等于声称自己是同一台设备，审计会直接点名
- **指纹脱敏（可在线扩表）** —— 出站前剥离上游内容审核黑名单指纹（键值段 / header 段 / 模板句最小改写）。
  内置规则是编译期常量；其上叠加一层**运行期自定义规则**（逐字 / 正则两种形态），
  后台增删即刻生效、**无需重新编译发布** —— 上游随时换指纹，而运维不必等下一个版本。
  三道安全网：保存即校验（含拒绝"能匹配空串"的正则）· 过宽自检（新规则必须让一组普通文本原样通过）·
  保存前试跑 + 对真实被拦样本回放（逐条给出命中样本数）。**内置规则只读，自定义只叠加不覆盖**
- **模型级限流精确对齐** —— 6004 只挡那一个模型（切模型立即可用），冷却截止对齐上游明示的重置时刻
  （body 文案 / 结构化字段 / 响应头三级解析）；拿不到时间信息时回落该模型的有界退避。
  账号卡列出「哪几个模型被限、何时恢复」，仪表盘单列一块**模型级冷却明细**，账号池可按「限模」筛
- **5xx 降档重试**（可选，默认关）—— 上游 5xx 时下沉到下一成本层继续救；因为会花更贵的额度，留给站长自己开

### 数据与备份（WAL）

SQLite 以 **WAL** 模式打开（默认 rollback journal 下每条 SQL 各 fsync 一次 —— 实测
建库要 1080 ms、单次写入 14 ms；WAL 后为 **88 ms / 0.5 ms**，测试包也因此从 10 分钟
超时降到约 65 秒）。

- 库旁边会有 `webapp.db-wal` 与 `webapp.db-shm`。**在线备份必须用 SQLite 自己的快照机制**，
  不能"三个文件一起 cp" —— 那只是三次独立的文件读取，中间可能落进一次写入，
  恢复时表现为"库能打开但账目对不上"（审查报告 F09）：
  ```bash
  # 方式 A（推荐，在线、不停服）：SQLite Online Backup API
  python3 - <<'PY'
  import sqlite3
  src = sqlite3.connect("data/webapp.db")
  dst = sqlite3.connect("data/backup-20261020.db")
  src.backup(dst)          # 一致性快照，包含 WAL 中已提交的内容
  dst.close(); src.close()
  PY

  # 方式 B（SQLite 3.27+）：VACUUM INTO 生成一份紧凑的单文件快照
  sqlite3 data/webapp.db "VACUUM INTO 'data/backup-20261020.db'"

  # 方式 C（冷备）：确认所有写入者都已停止后，再复制 db/wal/shm 三个文件。
  #   只停一半进程 = 没有一致性保证。
  ```
- 备份要**连 `secret.key`（凭证加密密钥）与 `admin.key` 一起**单独加密保存：
  只有 db 没有 secret key，恢复出来的账号全部解不开；
- 恢复后先跑 `PRAGMA integrity_check`，再核对余额/流水，最后才对外服务；
- **不要放在网络盘 / 云同步目录**（SMB、OneDrive 等）里运行 —— WAL 依赖共享内存；
- 可回退：`PRAGMA journal_mode=DELETE` 即切回，无需数据迁移。

### 可观测

- **实时面板口径完整** —— 曲线与事件流覆盖**全部** `/v1/chat/completions` 请求：
  被鉴权 / 余额 / 配额 / 限流 / 请求体校验提前拒掉的也在内（**兜底层统一补记**，同一请求只记一条）；
  失败事件带 HTTP 状态码与取自响应正文的真实原因，曲线用「柱内红段」表示该分钟失败占比；
  累计计数恒满足 `total == ok + fail`
- **模型级冷却识别两种上游形态**：4xx 响应体里的 `code=6004`，**以及已经 200 的流内 error 帧**
  （后者此前只透传给客户端、池侧不知道 → 不冷却 → 同模型请求反复撞同一个号）；
  两者共用同一套冷却原语，不存在两套口径
- **模型级冷却按 (账号, 模型) 粒度生效** —— 上游 6004（模型限额）只锁该模型，
  账号的其他模型照常服务；冷却期内选号、粘性命中校验、会话路由可用集三个入口走同一判定，
  **全冷却兜底也排除该模型仍在冷却的号**（宁可提前 503，不发必然失败的请求）；
- **模型级冷却的半开探测**（v0.31.6）—— 6004 的恢复时刻来自上游给的墙钟（封顶 24h），
  **上游提前解除**时我们无从得知，只能主动试出来：进入冷却 delay（默认 20m）后，若该模型
  确实已无可用号，系统会放行**一次**探测请求 —— 成功即**提前解除**该 (账号, 模型) 的冷却
  （一次成功往返是"已经恢复"的直接证据），失败则继续等墙钟，且**不延长**冷却
  （兜底探测不许把冷却越堆越厚，与账号级软冷却同一纪律）。
  三层强度闸门保证它不会变成对上游的轰炸：① 同一账号两次探测至少间隔 1h；
  ② **全池**同一模型两次探测至少间隔 5m（少这一层，客户端连续请求就会逐个号探一遍
  = N 次上游调用）；③ 一次客户端请求最多探测一次。可关停/调档：
  `-model-probe-delay` / `-model-probe-interval`（0 = 关停）/ `-model-probe-global`。
  台账可见：账号卡「模型级限额」行与 `/status` 的 `limited_models` 都带
  `probeable` / `probed_at` / `next_probe_at` —— 直接看出"什么时候会自动再试一次"。
  11102（该后端无此模型）**不探测**：重试无意义，恢复走自己的 TTL 到期 / 成功清理。

  上游给了重置时刻就按墙钟等（封顶 24h），**签到 / 探活 / 刷新余额都不再清它**
  （过去会被整表清空 → 冷却被截断到下次签到的间隔，且每次清空都放行一批必然失败的请求）
- **选号可观测** —— 均衡度指标（最高占比 / 覆盖账号数 / 偏斜倍数）+ **候选队列预览**（每个号为什么排这 / 为什么跳过）
- **选号轨迹** —— 同一会话是否换过号、换了几次，可复现查询
- **积分明细** —— 账号卡片直接展示积分包与到期进度条（走本地缓存，零额外出站）
- **健康检测** —— 快照式检测 + 时点观测失效机制，避免旧结论诱导重复操作
- **被拦样本回流**（可选）—— 被上游按内容策略拦下时留下 system 片段 + 工具名，供扩指纹黑名单；
  面板给出容量占用、按类型 / 按模型的分布与明细，并可一键清空
- **指纹规则面板** —— 样本 → 规则的闭环：内置规则只读列表 + 自定义规则增删 +
  试跑前后对照 + 对已采集样本回放（逐条命中数）；样本表每行可一键「采纳为规则」
- **消耗失败台账** —— 四阶段（预扣 / 上游 / 结算 / 扣费）的每一次失败结构化落表
  （错误码 · 阶段 · 上下文 · 重置来源），按码 / 阶段 / 窗口可查；错误码的处置口径由**声明式注册表**统一登记

### 请求链路

- **流式 / 非流式** —— SSE 帧按规范重建；出站强制 `stream:true`
- **统一出站改写** —— 角色归一 · `tool_choice` 归一 · `reasoning_effort` 档位降级 · 思维链回填 · 指纹脱敏（**单一入口，勿绕开**）
- **内容误拦自愈** —— 被上游内容策略拦截时同请求内换中性提示词重试一次，二次仍拦则如实返回
- **错误码映射** —— 按错误种类映射 400 / 404 / 429 / 503；**请求级错误不罚账号**；失败请求**不计费**（预扣全额退回）

### 定时积分任务

- **四类独立排程** —— 签到（09/21 点，末尾跑连登管家）· 活跃上报（10 点）· 猫猫旅行（09/21 点）· token 保活（22 点）
- **双域适配** —— 国内版与国际版各自独立路由与任务口径
- **任务台账** —— 执行结果、积分流水、失败原因分页可查

## 快速开始

**一个可执行文件**：网站 + 管理后台 + OpenAI 兼容网关，共用 8780 端口。

| 项 | 值 |
|---|---|
| 端口 | 8780（网站 / 管理后台 / `/v1` 网关共用） |

### 方式一：一键部署（推荐，不用装 Go）

**Windows** —— 双击仓库里的 [`deploy/quickstart-windows.bat`](deploy/quickstart-windows.bat)：
它会查最新版本 → 下载 → 解压到 `wb2api\` → 启动。全程不需要命令行。
也可以手动下载 Releases 里的 `wb2api-<版本>-windows-amd64.zip`，解压后双击 `start-webapp.bat`。

**Linux** —— 下载 Releases 里的 linux 包，解压后一条命令装成系统服务：

```bash
V=0.31.44   # 换成 Releases 里的最新版本号
curl -LO "https://github.com/sheng-du0521/workbuddy2api/releases/download/v$V/wb2api-$V-linux-amd64.tar.gz"
tar -xzf "wb2api-$V-linux-amd64.tar.gz" && cd "wb2api-$V"
sudo ./install.sh            # 装到 /opt/wb2api + systemd，自动打印管理密钥
# 容器里没有 systemd：./install.sh --no-systemd
```

装完浏览器打开 `http://127.0.0.1:8780/admin.html`，管理密钥在启动日志里，
也保存在 `data/admin.key`（Windows 是 `data\admin.key`）。

> 包内 `快速开始.txt` 是最短路径；`Web应用使用说明.md` 是完整说明（含各版本变更与排查）。
> **默认只监听 127.0.0.1**：别的机器访问不到，这是有意的安全默认值。要对外提供服务，
> 先改管理密钥、再加反向代理与 HTTPS，别直接把 `-addr` 改成 `0.0.0.0` 就扔公网。

校验发布包（每个包都附 `SHA256SUMS.txt`）：

```bash
sha256sum -c SHA256SUMS.txt                    # Linux
certutil -hashfile wb2api-*.zip SHA256         # Windows
```

### 出问题先看这里

| 现象 | 原因 / 处理 |
|---|---|
| 浏览器打不开 | 服务没起来或端口被占。看启动窗口/`journalctl -u webapp -n 50`；换端口改 `-addr` |
| 提示需要管理密钥但不知道是什么 | `data/admin.key` 的内容；或启动日志里「本次管理密钥」那一行 |

| 数据备份 | 停服务后拷 `data/webapp.db*`（含 `-wal`/`-shm`）；运行时直接拷可能少最后几条写入 |
| 装完 `systemctl status` 是 failed | 多数是端口占用或 `data/` 不可写；`journalctl -u webapp -n 50 --no-pager` 有原文 |

### 从旧网关 `wb2api`（7863）迁移

## 安全与合规

- **管理密钥**：`WB2API_ADMINKEY` 环境变量 > `data/admin.key` > 首次启动随机生成；
  比较用固定时间实现；**日志里只打脱敏值**；
- **凭证不回显**：设备凭证只回指纹与长度；账号 token 从不出现在任何响应里；
- **管理面加固**：CSRF（Origin / Referer 与 Host 比对）· Cookie `Secure` 自适应 ·
  按**真实客户端 IP** 限流（含桶回收）· 内部错误脱敏 · 请求体限 16 MB ·
  处理器 panic 兜底为可读的 500（细节只进日志）；
- **出口隔离**：账号可单绑线路；线路失效**默认不静默换出口**；任何情况下**不回落直连**；
- **发布包校验**：随包 `SHA256SUMS.txt` 可核对；发布脚本会断言包内不含密钥 / 数据库 / 明文 key。

**合规边界**：本项目是**非官方**网关，使用你自己的 CodeBuddy 账号作为上游，
**仅限本人授权账号、本机 / 私有环境**使用。使用者需自行遵守上游服务条款。

## 已知限制

- **Docker 起的是旧版产品** —— 见「快速开始 · 方式三」的说明；
- **出口线路需自备** —— 线路池能力完整，但**池里默认没有线路**，需要你填入自己的代理；
- **设备凭证需自备** —— `X-Device-Token` 由上游 SDK 签发，必须从桌面端抓包取得后逐号录入
  （本项目**不会**伪造该值，自编值比不带更容易被判异常）。可选的「派生兜底」只在三档全空时
  按 uid 合成一个互异值（**合成 ≠ 真凭证**，仅用于消掉"全池都不带该头"这一种聚类形态）；
- **版本更新提醒只提醒、不自动更新** —— Windows 上运行中的 exe 无法原地覆盖，且更新通道是
  供应链攻击最肥的目标，只提醒就不存在这个攻击面。提醒的可用性取决于清单地址是否可达：
  `raw.githubusercontent.com` 在部分网络下不通，此时会自动回退到
  `api.github.com` / `cdn.jsdelivr.net` / `ghproxy.net`（**只对 GitHub raw 形态的地址派候选**，
  自建清单地址不派生）；
- **消耗失败台账有上限**（默认 5000 行，超出丢最旧）：它是"每次失败都写一行"的表，
  而失败率最高的时段正是它涨得最快的时候，所以按行数封顶而不是按天（按天在错误风暴下会失控）。
  代价是错误风暴时段更早的记录会被更近的挤掉 —— 界面会显示当前占用 / 上限；
- **模型级冷却的半开探测有代价与边界**（v0.31.6 起已实现，见上文）—— 探测是真发上游请求，
  故强度被三层闸门限死（同号 1h / 全池同模型 5m / 每请求 1 次），代价是"上游提前解除"最多要
  等一个间隔才会被发现；且只有 6004 可探（11102 重试无意义）。生产池长期没有 6004 条目时，
  这条路径不会被触发（也就没有真实上游的长期观察数据）；
- **并发窗口内仍可能重复调度**（v0.31.7 起已做**软偏好**缓解）—— 冷却是「上一次响应到达后」
  才写入的，同一 (账号, 模型) 的并发请求会在 6004 回来之前各自选号。现在该 (账号,模型) 已有
  在途请求时会**优先换号**（计数 `model_busy_skips` 见 `/api/admin/live` 的 `route` 块），
  但**只剩它可用时仍会重复调度**（可用性优先，刻意的取舍）—— 属固有竞态；
- **模型名按原样字符串做冷却键**（未做 TrimSpace / 大小写 / 前缀归一）——
  客户端混用写法会被当成两个模型；
- **路由侧计数** —— `/api/admin/live` 的 `route` 块：`model_inflight`（当前有在途请求的
  (账号,模型) 键数）与 `model_busy_skips`（因该键"忙"而改选别的号的累计次数）。
  长期为 0 = 并发重复调度在实践中没发生；涨起来就是"该升级为硬互斥"的证据；
- **实时面板是内存态** —— 重启即清空、窗口 60 分钟（刻意的：它不该被当账本，账在 `usage_logs`）；
  被前置拒绝的请求在事件里**不带 model**（那时请求体还没被解析），显示为 `—`；
- **请求体 / 响应体内容默认不留存** —— 只记录元数据（模型 / Token / 上游账号 / 扣费 / 会话键）。
  唯一例外是**可选开启**的「被拦样本回流」：开启后只落 **system 提示词前 300 字 + 工具名**
  （不落用户消息、不落整个请求体）。默认关闭；
- **自定义指纹规则的"有效性"只能靠回放间接证明** —— 回放给出的是"这条规则命中了 N 条被拦样本"，
  它**不能证明**上游因此不再拦截；终局证据只能是"改完之后同类请求不再被拦"，需要真实流量观察。
  同理，"过宽自检"用的普通文本语料是有限的（6 条），能挡住明显过宽的规则，
  但挡不住语义上更隐蔽的过度改写；正则形态也只保证不死循环 / 不放大请求体，
  不做"这个正则的语义范围是否合理"的判断；
- **自动审核是高风险配置** —— 可配「自动审核」（提交即通过并打款）与免审额度上限，
  但不含金额分级审批、多级复核、异常额度熔断等更进一步的保护；
  写入设置时非法取值**显式拒绝**（不静默回落），读取时垃圾值**回落人工审核**；
- **本仓库只放源码** —— 使用说明、发布包、调研与事件记录不在仓库内（见 `.gitignore`）。
