号池账号

勾选卡片左上角的方框即可挑出任意账号（可跨分组、跨筛选）做批量设置： 有勾选时「批量设置」只作用于勾选的账号，没有勾选时才作用于当前筛选出的全部账号。
成长任务按同一套勾选挑选：勾好账号后点「跑成长任务」；跑单个号直接点账号卡上的 「成长任务」标签。它是手动执行、不自动排程，后台逐个串行、账号之间会随机等待， 结果见「执行台账」。
消耗分组决定账号是否参与平台消耗：用户申请（优先）→ 反代（次级）； 预备 / 闲置 / 异常不参与。「预备」由系统把已入池但积分低于 100 的账号自动搬入，积分回到 2000 自动回流「用户申请」；「异常」由系统在消耗中发现无法扣积分 / 被封号时自动归档， 积分不足类在冷却到期后自动回归原组，封号类需重登后人工改回。

健康检测

对每个账号发两次探活：① 查余额接口（不消耗积分）；② 发一次极小的真实对话 （单轮 "hi"、max_tokens=1，不写账单、不扣用户点数，但确实是一次出站对话请求）。 两次都通才算「能服务用户」—— 实测存在余额全通、对话全被拦的账号， 只查余额会给出虚假的安心结论。
判定项：登录是否失效、是否被 WAF 拦、权限或试用是否开通、余额是否耗尽、 对话通道是否可用。
确定性异常会自动处置：上游明说「账号存在异常行为，已被限制使用」→ 即时上报并立即删除 （账号级判定，等累计没意义）；裸 11140 请求非法连续 3 次后删除（可恢复抖动，故给 3 次机会）； 登录失效累计后禁用；余额耗尽冷却到次日 4 点并归档。 不确定的结果只报告不动账号 —— 被 WAF 拦 / 限流 / 上游 5xx 指向的是出口或上游，不是账号本身。
检测还顺带刷新权威余额并按余额收敛消耗分组；批量导入账号时会自动跑一次， 结果同样出现在下面（来源标注「导入后自动」）。
只看结论、不改状态的项：降权中（冷却 / 熔断 / 连败）表示凭证是好的但当前 不参与选号；被系统禁用但探测通过的号会提示可考虑复活（不会自动复活）。
挑选要检测的账号去「账号池」页勾选（本页只提供入口，不重复一份账号列表）， 勾选状态跨页保留。

代理

代理分两层，别混：出口代理管「有哪些 IP 可以出去」（线路池：录入、探活、分配）； 账号代理管「这个号实际从哪出去」（三态：未指定 / 显式直连 / 指定线路）。 同一条线路可以被多个号绑定，但同一号主的多个号不该共用出口 —— 同人多账号同 IP 是上游最强的关联信号。

先记一条硬约束

本服务的上游是 copilot.tencent.com / www.codebuddy.cn（国内域名）， 而账号本身也是国内账号。所以：
  • 出口必须能访问国内网络（海外出口访问国内上游本身就慢且不稳）；
  • 账号属地 ≠ 出口属地本身就是异常特征 —— 「国内号常年从某境外机房 IP 访问」比直连更像风险信号；
  • 结论：不要买海外住宅代理 / 不要拿境外 VPS 当出口。 这一点与「住宅 IP 更抗识别」的通用经验不同，是本项目特有的约束。
例外：若你的账号本身就是海外属地（国际版），那出口应落在对应地区。 原则始终是「出口属地与账号属地一致」。

渠道对照：按适合度排序

选代理的硬指标是 IP 数量够 / IP 干净 / 长期固定 / 国内可达，不是「速度快」。
渠道出口类型适合度说明
国内独享 / 静态住宅代理 真住宅 生产首选 一号一 IP、长期固定，最贴合「一个账号一个家」的形态；按 IP 月租
动态拨号 VPS 自建 运营商拨号 性价比好 一个 VPS 一个拨号出口，重启可换 IP；几十元/月，适合中小规模
国内云服务器自建（3proxy / tinyproxy） 机房 一般 独享可控、便宜、部署简单，但机房 IP 风控识别度高，适合低敏感场景
国内动态短效住宅（按量提取） 真住宅 谨慎 便宜，但 IP 会变 → 同一账号多 IP 反而更可疑，且与粘性会话冲突
公开免费代理 混杂 不要用于生产 本项目实测可用率约 0.9%，且画像比干净的本机 IP 更差 （见随包的 免费代理测试报告.md）；只适合验证链路
海外住宅 / 海外 VPS 境外 不适用 与上游和账号属地都不匹配，见上方硬约束
结论：账号数 ≈ 需要的 IP 数。先按账号数估需要几条线路，再决定自建还是买服务。
本项目不为任何服务商背书，下面只给类型与检索关键词 —— 别照抄名字就下单， 一定先用「保存并探活」和小额测试验一遍。

方案 A：自建（推荐起步，中小规模）

  1. 买机器：国内云厂商的轻量应用服务器 / 按量计费实例（阿里云、腾讯云、华为云等）， 或动态拨号 VPS（重启换 IP 更省事）。要几个 IP 就开几台， 尽量分散到不同地域 / 不同供应商 —— 同一个 /24 段开一堆，等于没隔离。
  2. 装代理服务端：只做出口代理不必上复杂方案， 3proxy（HTTP + SOCKS，配置一行起）或 tinyproxy（纯 HTTP）最省事； 需要加密传输再考虑 sing-box / Xray。
  3. 拿到 URL：配好后会得到形如 http://user:pass@1.2.3.4:8080 或 socks5://user:pass@1.2.3.4:1080，粘到上面「添加线路」即可。
  4. 务必加认证：user:pass 不能省。裸代理端口会在几小时内被全网扫到， 被扫到就等于出口 IP 被别人共用 —— 反而把自己拖进风控。
  5. 防火墙：只放行代理端口；SSH 改非 22 端口或只允许密钥登录。
一台机器要多个出口：云厂商可挂多个弹性 IP，服务端按入站端口把流量分流到不同出口 IP （3proxy 的 internal/external 多段配置即可）—— 能显著摊薄单 IP 成本。

方案 B：买商业代理

  • 国内独享静态住宅（首选）：检索「独享静态住宅代理」「固定 IP 代理 月租」。 要点是按 IP 月租 + 独享 + 可长期续用，而不是买「IP 池按量提取」。
  • 国内动态提取型：检索「动态代理 IP」「隧道代理」。 按提取量或并发计费，IP 池大但单 IP 存活短 —— 不适合「一个账号固定一个 IP」，更适合做出口池轮换。
  • 选型时问清三件事：① 出口是不是真住宅/移动（而不是机房混住宅）； ② 是否独享（共享池里同 IP 可能已有陌生人滥用）； ③ 支持哪些协议（本项目要 http/https/socks5， 不支持 socks5h）。
  • 计费：优先「按量 / 可冻结」，避免买了用不上的配额。

用随包工具先验证（强烈推荐）

宣传的可用率不能信，要用真实业务路径验。仓库自带 tools/proxyscan： 并发探测并同时验证两个真实上游 —— 只通一个的代理会出现 「对话能通、计费查询全挂」这种半死状态，必须两个都过才算可用； 并且默认启用严格 TLS 校验，会自动排除做 MITM 解密 token 的代理。 
export PATH="$PATH:/c/Program Files/Go/bin"
# 1) 快速初筛（只测国内可达）
echo "1.2.3.4:8080" > cand.txt
go run ./tools/proxyscan -in cand.txt -scheme http -c 50 -t 8 -out good.txt
# 2) 对通过的做真实双上游复验（严格 TLS 默认开启）
go run ./tools/proxyscan -in good.txt -scheme http -c 20 -t 8 -out final.txt
只买了少量线路的话，也可以直接用本页上方「保存并探活」单条验（回显真实出口 IP）。

怎么判断一条代理能不能用

  • 能回显真实出口 IP —— 探活通过且 IP 落在国内（或与该账号属地一致）。 探活会依次尝试多个公共回显端点；端点全不可达时判为「不确定」而不是「线路坏了」。
  • 是独享还是共享 —— 出口 IP 若被成百上千人共用（免费代理、廉价共享池）， 这个 IP 在你拿到之前就已经脏了。
  • 稳定性 —— 本页每 5 分钟自动探活，连续 3 次失败会自动停用。 频繁被停用的线路别留在池里。
  • 延迟 —— 探活回显里带耗时；>800ms 会显著拖慢对话类接口的首字节时间。
  • IP 是否固定 —— 同一账号应长期用同一个出口。IP 频繁漂移本身就可疑， 所以「独享静态」优先于「动态提取」。

几条容易踩的坑

  • 别把所有号塞进一条线路 —— 同出口账号数超过上限时页面会告警。 上限可在「设置」页调，但放宽只是掩盖风险，不是消除风险。
  • 同一号主的多个号必须分开 —— 这是本项目里最强的关联信号， 批量分配默认就带「同号主不共用出口」约束，别关掉。
  • 改完代理要留意出口异常 —— 代理填错或探活失败时该账号会被自动排除出平台选号 （运行期绝不回落直连），修好或改回「直连」即恢复。
  • 「清空」不等于「直连」 —— 清空是回到「未指定」，此时若配了全局默认代理， 账号会走默认那条；要真的走本机 IP，用「直连」。
  • 环境变量代理 —— 后端进程若有 http_proxy/https_proxy 环境变量，「未指定」的账号也会受其影响；「显式直连」是唯一能绕过它的状态。
  • 别一次全量切过去 —— 先买 2~3 条线路、一条挂 2~3 个号，跑 1~2 周看账号健康度 （签到是否正常、有无异常归档），确认稳定后再扩量。
  • 合规 —— 代理只用于你自己账号的出口隔离； 使用前请自行确认符合目标服务的服务条款与你所在地区的法律法规。 本项目不提供任何绕过法律或平台规则的用途。

导入防关联 · 积分补新

        

          为什么要有这一组：同一出口 IP 上短时间内冒出一批新号，是比「多个号长期共用一条宽带」
          更强的聚类信号 —— 后者可能是自然用户，前者不像。所以批量导入要走门禁：
          每批不超过 N 个，且每批之间换一次出口 IP。
          
⚠️ 典型家宽拓扑下，公网 IP 在光猫上（本机 → 二级路由 → 光猫 → ISP）。

本程序不保存、也不会去猜你的光猫密码：默认是「你去重启，回来点一下，程序实测确认 IP 真变了才放行」。
          如果你有智能插座或路由器 API，可以在下面填一条命令，之后就能全自动换 IP。

              命令原样保存在本机数据库，能改它的人本来就能改整个网关配置；程序绝不接受来自导入接口的命令。

设备风控凭证（X-Device-Token）

        

          为什么重要：X-Device-Token 是本项目逆向资料里唯一有实证的风控头
          （其余 X-Machine-ID / X-Session-ID 只是"行业对齐"）。官方客户端恒带它 ——
          一个长跑的中转站从来不带，这本身就是稳定的客户端差异，而稳定差异正是可被聚类的特征。
          
来源优先级：账号自带 device_token > 全局值（环境变量 WB2API_DEVICE_TOKEN > 下面这项）
          > 文件。三者皆空则不注入该头。
          
理想状态是一号一凭证（账号卡上显示「设备凭证」绿标）；全局兜底是"共享一个"，比裸奔好但不是最优。
        

        

          

            
            
            

          

          

            
            
            
把凭证写在文件里再填路径（与「共用桌面端状态文件」的部署方式一致）。
              文件非空才生效，程序每 5 分钟重读一次。

          

        

        

          
          
          
        

      


      

        
关于 · 版本更新提醒

        

          本功能只提醒，不自动更新。检查在后台异步进行（启动 25 秒后一次，之后每 12 小时一次），
          结果缓存 12 小时 —— 打开页面不会因为"查更新"而变慢；缓存新鲜时完全不出站。
          
检查失败静默：离线、DNS 失败、被代理拦、被 CDN 限流，一律不影响主功能，

          且更新通道是供应链攻击最肥的目标，只提醒就不存在这个攻击面。

用户代挂 · 分成 / 返点

        

          用户的代挂账号经审批进入号池后参与平台反代。每完成一次请求，平台按
          该次消耗的号池积分 × 分成比例折入号主余额（固定分成比例）——
          基数取积分本身，不随计费倍率缩放，所以调倍率不会压缩号主收益。
          
但分成以该次平台实收为上限：当「计费倍率 < 分成比例」时分成会被压到实收，
          平台不倒贴。想让平台每次都有留成，请保证 计费倍率 > 分成比例。
          0 = 关闭分成。用户在控制台可自助申请/退出。
          
另设推广返点比例：下级兑换充值码、以及下级的代挂账号在号池赚到收益时，
          上级按该比例拿返点（返点从平台留成中出，不会侵占号主分成）。
          
这两个比例是「全局默认」。可在「用户」页对单个用户单独设定（覆盖全局）——
          用户卡片上的「号池分成 / 推广返点」标签点开即可编辑；留空 = 恢复跟随全局。
          单用户覆盖只影响其之后的入账，不追溯重算历史流水。
        

        

          

            
            
            
如 0.6 = 号主拿积分的六成。需小于计费倍率才有平台留成。可对单个用户在「用户」页单独覆盖。

          

          

            
            
            
如 0.1 = 下级每充值/赚收益 100 点，上级拿 10 点。0 = 关闭推广返点。可对单个用户在「用户」页单独覆盖。
